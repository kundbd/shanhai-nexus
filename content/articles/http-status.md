## 适用条件

适用于已经取得 HTTP 响应的网页和 API 请求。若没有响应，先检查网络或 TLS 错误。

## 操作步骤

### 1. 找到实际失败的请求

浏览器打开开发者工具的「网络」面板，重试一次操作，选中对应请求并记录状态、方法与路径。

### 2. 读取响应正文和头部

同一状态码在不同接口可能对应不同错误。优先查看服务商返回的错误类型，并记录请求 ID 与时间。脱敏后再分享。

### 3. 按错误类别验证

对于客户端侧错误，核对凭据、请求格式或权限。遇到服务端错误先查看服务状态，小间隔避免批量重试。

## 常见问题

### 状态是 200，页面为什么还报错？

应用可能把业务错误写入响应正文，或返回了登录页面。核对 Content-Type 与响应内容。
